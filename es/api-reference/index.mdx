# API Reference

La API de Facturear te deja emitir facturas electrónicas de ARCA desde tu propio sistema, consultar su resultado, descargar el PDF y el XML, mandarlas por email y administrar tus CUITs, borradores y webhooks. En la sección **API Endpoints** está cada operación con sus parámetros y respuestas.

## Autenticación

Cada pedido lleva tu API Key en el header `x-api-key`:

```bash
curl https://www.facture.ar/api/invoices \
  -H "x-api-key: test_sk_..."
```

Sin key, o con una key que ya no es válida, la API responde `401` con `code: "unauthorized"`. La API REST no acepta otra credencial: siempre va la API key en `x-api-key`.

### Una key por entorno

La URL es la misma para los dos entornos. El entorno lo decide la key:

| Prefijo | Entorno | Qué hace |
|---|---|---|
| `test_sk_` | Testing (homologación de ARCA) | Emite comprobantes de prueba, sin validez fiscal |
| `prod_sk_` | Producción | Emite comprobantes reales, con validez fiscal |

Con una API Key, el header `x-environment` y el parámetro `environment` se ignoran.

<Warning>
  Las facturas que emitís con la key de producción son reales. Para probar, usá la key de testing. Ver [Entorno de testing](/es/guides/entorno-testing).
</Warning>

### Obtener tu API Key

1. Entrá a tu cuenta en [facture.ar](https://www.facture.ar/?utm_source=docs&utm_medium=referral&utm_campaign=api-reference-index&utm_content=link)
2. En el menú lateral, en **Desarrolladores**, entrá a **Claves API**
3. En la tarjeta **Producción** o **Testing**, tocá **Generar clave**
4. Copiala con **Copiar** y guardala en un lugar seguro

La key completa se muestra **una sola vez**, cuando la generás: Facturear guarda solo un hash, así que después en el panel ves apenas el principio y el final (`prod_sk_…1a2b`). Si la perdiste, regenerala.

Con **Regenerar** obtenés una key nueva: la anterior deja de funcionar en el acto. Ver [API Keys](/es/guides/api-keys).

## URL base

```
https://www.facture.ar/api
```

Usá siempre la dirección con `www`. Si llamás a `facture.ar` sin `www` y el pedido pasa por una redirección, algunos clientes HTTP convierten el `POST` en `GET` o pierden el body.

## Formato del body

Mandá el body como `application/json` (podés agregar parámetros como `; charset=utf-8`). `POST /invoices` acepta además `application/xml`. Un JSON mal formado responde `400`.

Para emitir, el importe va en `impTotal`, el total del comprobante con IVA y tributos incluidos. El campo `amount` ya no se acepta: un pedido que lo manda sin `impTotal` responde `400`.

```bash
curl -X POST https://www.facture.ar/api/invoices \
  -H "x-api-key: test_sk_..." \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f1c2b0e-8a43-4c5e-9d2a-3b7f1e0c9a11" \
  -d '{ "impTotal": 12100, "concepto": 2, "docTipo": 80, "docNro": 20123456789 }'
```

## Errores

Todos los errores `4xx` de la API (y los `503` temporales) siguen el formato **RFC 9457** (`Content-Type: application/problem+json`):

```json
{
  "type": "https://www.facture.ar/problems/plan_required",
  "title": "Forbidden",
  "status": 403,
  "code": "PLAN_REQUIRED",
  "detail": "...",
  "error": "...",
  "message": "...",
  "resolution": "...",
  "upgradeUrl": "https://www.facture.ar/..."
}
```

| Campo | Qué es |
|---|---|
| `code` | Código estable para tu programa (ver la tabla de abajo) |
| `detail` / `message` | Qué pasó, en texto |
| `resolution` | Qué hacer para resolverlo |
| `error` | El mismo texto de siempre, para los clientes que ya leían `error` |
| `details`, `upgradeUrl`, `creditNoteId`, `batchId`, `maxCuits` | Los campos de antes, cuando corresponden: errores de validación, dónde cambiar de plan, la nota de crédito que ya anuló una factura o el lote donde sigue en curso |

Los `code` que te conviene manejar:

| Estado | `code` | Cuándo |
|---|---|---|
| 400 | `invalid_request` | Body o parámetros inválidos; `details` lista los campos |
| 401 | `unauthorized` | Falta la API key o no es válida |
| 403 | `PLAN_REQUIRED` | El plan Free emite en producción solo a mano desde la web: la API, el MCP y los lotes en producción necesitan un plan pago |
| 403 | `PLAN_REGIME` | El plan Monotributo mandando un tipo que no es C ni E |
| 403 | `SUBSCRIPTION_LIMIT_EXCEEDED` | Se agotaron las facturas o el monto del mes de tu plan, o llegaste al límite de CUITs (`maxCuits`) |
| 403 | `TEST_KEY_READ_ONLY` | Una key de testing intentó cambiar la configuración de la cuenta (CUITs, webhooks, plantillas) |
| 404 | `not_found`, `cuit_not_found` | El ID no existe en tu cuenta o es del otro entorno |
| 409 / 422 / 400 | `IDEMPOTENCY_KEY_IN_PROGRESS`, `IDEMPOTENCY_KEY_REUSED`, `IDEMPOTENCY_KEY_INVALID` | Problemas con el `Idempotency-Key`. Ver [Reintentar sin duplicar facturas](/es/guides/idempotencia) |
| 429 | `rate_limited` | Pasaste el límite de pedidos por minuto |
| 429 | `email_limit_reached` | Límite de envíos por email de una factura o del mes |
| 503 | `service_unavailable` | ARCA o la importación no están disponibles en este momento; reintentá en unos minutos |

Los límites del plan solo aplican en producción: en homologación podés emitir sin límite con cualquier plan.

Si el cuerpo no es JSON válido, la respuesta es un `400` con `code: "invalid_request"`.

## Límite de pedidos

Todas las API keys de una cuenta y un entorno comparten un tope de **1800 pedidos por minuto**. Si lo pasás, la API responde `429` con `code: "rate_limited"` y los headers `Retry-After` (segundos a esperar) y `RateLimit-Limit`. Para emitir muchas facturas, mandá un array de hasta 500 en un solo `POST /invoices` en vez de un pedido por factura.

## Especificación OpenAPI

La sección **API Endpoints** sale de la especificación completa de esta documentación. Además, la app publica en [`https://www.facture.ar/openapi.json`](https://www.facture.ar/openapi.json) la especificación pensada para agentes de IA: facturas (crear, listar, consultar, PDF, XML, enviar por email y anular con nota de crédito), lotes, webhooks con sus eventos y firma, y los documentos públicos de descubrimiento (`/api/v1`, `/api/v1/sandbox`). Es la que citan los mensajes de error en `resolution`. Ahí las rutas llevan el prefijo `/api` completo (`/api/invoices`); acá la URL base ya lo incluye.

## Webhooks

Para enterarte de lo que pasa con tus facturas sin consultar la API, registrá un webhook. Eventos, payloads, cómo verificar la firma y reintentos: [Webhooks](/es/api-reference/webhooks).
