# Webhooks

Un webhook es una URL de tu servidor a la que Facturear le manda un `POST` cada vez que pasa algo en tu cuenta: ARCA autorizó una factura, una factura falló, terminó un lote, llegó una comunicación de ARCA. Así tu sistema se entera en el momento, sin tener que consultar la API cada tanto.

## Crear y administrar webhooks

Tenés dos caminos:

- **Desde el panel**: en [facture.ar/app/webhooks](https://www.facture.ar/app/webhooks?utm_source=docs&utm_medium=referral&utm_campaign=api-reference-webhooks&utm_content=link) tocá **Agregar webhook**, poné la URL, elegí los eventos y, si querés, headers propios. Desde la lista podés pausarlo o activarlo, editarlo, eliminarlo, ver el **Secreto de firma** y las **Entregas**.
- **Desde la API**:

| Método | Endpoint | Qué hace |
|---|---|---|
| `GET` | `/api/webhooks` | Lista los webhooks de la cuenta (sin el secreto) |
| `POST` | `/api/webhooks` | Crea uno. Body: `url`, `events` y, opcional, `headers`. Responde `201` con el webhook y su `secret` |
| `PUT` | `/api/webhooks/{id}` | Cambia solo los campos que mandás: `url`, `events`, `headers` (`null` los borra) o `isActive` (`false` lo pausa) |
| `DELETE` | `/api/webhooks/{id}` | Lo borra; no se le mandan más eventos |

La URL tiene que ser `https` y con una dirección pública (no se aceptan `localhost` ni IPs privadas).

Los webhooks son configuración de la cuenta y los comparten los dos entornos: cada evento dice en `environment` si viene de homologación o de producción. Por eso, para crearlos, editarlos o borrarlos por API hace falta la **key de producción**: con una key de testing, esos pedidos responden `403` con `code: "TEST_KEY_READ_ONLY"` (listarlos sí se puede).

```bash
curl -X POST https://www.facture.ar/api/webhooks \
  -H "x-api-key: prod_sk_..." \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://tu-servidor.com/webhooks/facturear",
    "events": ["invoice.completed", "invoice.failed"]
  }'
```

<Note>
  La respuesta del `POST` trae el secreto de firma (`whsec_...`). Es la única vez que la API lo devuelve: guardalo. Después lo ves en el panel, en **Secreto de firma**.
</Note>

## Eventos

| Evento | Cuándo se manda |
|---|---|
| `invoice.completed` | ARCA autorizó una factura (tiene CAE). Una sola vez por factura |
| `invoice.failed` | Una factura falló definitivamente: ARCA la rechazó o se agotaron los reintentos automáticos. Si la reintentás a mano y vuelve a fallar, llega otro |
| `batch.completed` | Un lote terminó (`completed`, `completed_with_errors` o `error`). También una factura suelta, que es un lote de una |
| `draft.review_required` | Un borrador espera tu revisión: quedó con observaciones, no se pudo leer el documento, o en modo automático no se pudo emitir |
| `dfe.message.received` | Llegó una comunicación nueva al Domicilio Fiscal Electrónico de un CUIT (sincronización diaria con ARCA). Siempre `environment: "production"` |
| `tax_account.updated` | Cambió el saldo del Sistema de Cuentas Tributarias de un CUIT (sincronización diaria con ARCA). Siempre `environment: "production"` |

## Payload

Cada envío es un `POST` con `Content-Type: application/json`. El body siempre trae estos campos, más los del evento:

| Campo | Qué es |
|---|---|
| `id` | ID del evento (`evt_...`). Es el mismo si la entrega se reintenta: usalo para no procesar dos veces el mismo evento |
| `event` | El nombre del evento |
| `environment` | `production` o `homologation` |
| `timestamp` | Cuándo se armó el evento, ISO 8601 |

## Headers

| Header | Qué es |
|---|---|
| `Facturear-Signature` | `t=<segundos unix>,v1=<firma en hex>`. La firma es un HMAC-SHA256 de `"<t>.<body crudo>"` con el secreto `whsec_...` del webhook |
| `Facturear-Event` | El nombre del evento, igual que `event` en el body |
| `Facturear-Delivery` | ID de esta entrega. Los reintentos automáticos de una entrega lo mantienen; un reintento manual desde el panel es una entrega nueva, con otro ID |
| `Content-Type` | `application/json` |
| `User-Agent` | `Facturear-Webhook/1.0` |

Además van los headers propios que configuraste en el webhook. No pueden reemplazar `Facturear-Signature`, `Facturear-Event` ni `Facturear-Delivery`.

## Verificar la firma

Verificá cada envío antes de hacerle caso. Los pasos:

1. Leé el body **crudo**, tal cual llegó, sin parsearlo.
2. Del header `Facturear-Signature`, sacá `t` y los `v1` (separados por coma).
3. Calculá el HMAC-SHA256 en hex de `"<t>.<body crudo>"` con tu secreto `whsec_...` (el secreto completo, con el prefijo).
4. Comparalo con cada `v1` en tiempo constante.
5. Rechazá el envío si `t` está a más de **300 segundos** de tu reloj: así nadie puede reenviarte una entrega vieja.

### Node.js (Express)

```javascript
const crypto = require('crypto');
const express = require('express');

const SECRET = process.env.FACTUREAR_WEBHOOK_SECRET; // whsec_...
const TOLERANCE_SECONDS = 300;

function verifyFacturearSignature(secret, rawBody, header) {
  if (!header) return false;
  let timestamp = null;
  const signatures = [];
  for (const part of header.split(',')) {
    const [key, value] = part.trim().split('=', 2);
    if (key === 't' && /^\d+$/.test(value || '')) timestamp = Number(value);
    if (key === 'v1' && value) signatures.push(value);
  }
  if (timestamp === null || signatures.length === 0) return false;

  const expected = Buffer.from(
    crypto.createHmac('sha256', secret).update(`${timestamp}.${rawBody}`, 'utf8').digest('hex'),
    'hex'
  );
  const matches = signatures.some(signature => {
    const received = Buffer.from(signature, 'hex');
    return received.length === expected.length && crypto.timingSafeEqual(received, expected);
  });
  if (!matches) return false;

  const now = Math.floor(Date.now() / 1000);
  return Math.abs(now - timestamp) <= TOLERANCE_SECONDS;
}

const app = express();

// express.raw: el body llega como Buffer, sin parsear
app.post('/webhooks/facturear', express.raw({ type: 'application/json' }), (req, res) => {
  const rawBody = req.body.toString('utf8');
  if (!verifyFacturearSignature(SECRET, rawBody, req.get('Facturear-Signature'))) {
    return res.status(400).send('Firma inválida');
  }

  const event = JSON.parse(rawBody);
  res.status(200).send('ok'); // respondé rápido y procesá aparte

  // Usá event.id para no procesar dos veces el mismo evento
  if (event.event === 'invoice.completed') {
    console.log('Factura autorizada', event.invoice.id, event.invoice.cae);
  }
});

app.listen(3000);
```

### Python (Flask)

```python
import hashlib
import hmac
import json
import os
import time

from flask import Flask, request

SECRET = os.environ["FACTUREAR_WEBHOOK_SECRET"]  # whsec_...
TOLERANCE_SECONDS = 300


def verify_facturear_signature(secret: str, raw_body: bytes, header: str | None) -> bool:
    if not header:
        return False
    timestamp = None
    signatures = []
    for part in header.split(","):
        key, _, value = part.strip().partition("=")
        if key == "t" and value.isdigit():
            timestamp = int(value)
        if key == "v1" and value:
            signatures.append(value)
    if timestamp is None or not signatures:
        return False

    signed = f"{timestamp}.".encode("utf-8") + raw_body
    expected = hmac.new(secret.encode("utf-8"), signed, hashlib.sha256).hexdigest()
    if not any(hmac.compare_digest(expected, signature) for signature in signatures):
        return False

    return abs(int(time.time()) - timestamp) <= TOLERANCE_SECONDS


app = Flask(__name__)


@app.post("/webhooks/facturear")
def facturear_webhook():
    raw_body = request.get_data()  # bytes crudos, antes de cualquier parseo
    if not verify_facturear_signature(SECRET, raw_body, request.headers.get("Facturear-Signature")):
        return "Firma inválida", 400

    event = json.loads(raw_body)
    # Usá event["id"] para no procesar dos veces el mismo evento
    if event["event"] == "invoice.completed":
        print("Factura autorizada", event["invoice"]["id"], event["invoice"]["cae"])
    return "ok", 200
```

### Errores comunes

- **Parsear el JSON antes de verificar.** Si tu framework ya parseó el body y lo volvés a serializar, cambian espacios u orden de los campos y la firma no coincide. Verificá sobre los bytes que llegaron (`express.raw`, `request.get_data()`, `await request.body()` en FastAPI).
- **Usar el secreto sin el prefijo.** El secreto es el texto completo, `whsec_` incluido.
- **Comparar con `==`.** Usá una comparación en tiempo constante (`crypto.timingSafeEqual`, `hmac.compare_digest`).
- **Reloj del servidor corrido.** Con más de 300 segundos de diferencia, las firmas válidas se rechazan. Sincronizá la hora con NTP.
- **Usar un secreto viejo.** Si rotaste el secreto, el anterior deja de servir en el acto.

## Entregas y reintentos

- **Éxito**: cualquier respuesta `2xx` dentro de los **10 segundos**. Un `3xx` cuenta como falla: las redirecciones no se siguen, así que usá la URL final.
- **Reintentos automáticos**: si tu servidor no responde a tiempo, falla la conexión o responde algo que no es `2xx`, se reintenta enseguida (a 1 y 2 segundos), hasta **3 intentos** en total. Cada intento se firma con su propio `t`; el `Facturear-Delivery` y el body son los mismos.
- **Después de 3 intentos** la entrega queda como fallida y no se reintenta sola.
- **Entregas en el panel**: en [facture.ar/app/webhooks](https://www.facture.ar/app/webhooks?utm_source=docs&utm_medium=referral&utm_campaign=api-reference-webhooks&utm_content=link), **Ver entregas** muestra cada envío con su evento, estado, código de respuesta, el payload y los headers que mandamos, y el principio del body que respondiste. Con **Reintentar** volvés a mandar una entrega: va con el mismo body (mismo `id` de evento), la URL, los headers y el secreto actuales del webhook, y un `Facturear-Delivery` nuevo.
- **Sin duplicados de nuestro lado**: cada evento se arma una sola vez (por ejemplo, un `invoice.completed` por factura). Igual pueden llegarte repetidos por los reintentos o por un reintento manual, así que deduplicá por el `id` del body.

<Tip>
  Respondé `200` apenas verificaste la firma y procesá el evento aparte (una cola, un job). Si tu proceso tarda más de 10 segundos, la entrega se da por fallida y se reintenta aunque la hayas procesado.
</Tip>

## Secreto de firma

- Se genera al crear el webhook: `whsec_` y 48 caracteres hexadecimales.
- La API lo devuelve solo en la respuesta del `POST /api/webhooks`. `GET` y `PUT` no lo incluyen.
- En el panel lo ves con **Secreto de firma**, y con **Rotar secreto** generás uno nuevo. La rotación es inmediata: el secreto anterior deja de verificar en el acto, así que actualizalo en tu servidor enseguida.
