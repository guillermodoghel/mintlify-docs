# Entorno de testing (homologación) en Facturear

Antes de conectar tu sistema con producción y emitir facturas reales, podés usar el **entorno de homologación (testing)** de ARCA. Este entorno te permite probar toda la integración sin impacto fiscal real.

---

## ¿Qué es el entorno de homologación?

ARCA ofrece un entorno de **homologación** (también llamado "testing") que replica el comportamiento del webservice de facturación electrónica, pero las facturas emitidas ahí **no tienen validez fiscal**.

- Los CAEs emitidos en testing son "de prueba"
- No se informan al sistema fiscal real
- Podés emitir tantas facturas de prueba como necesités

---

## Configuración en Facturear

No tenés que configurar nada aparte: al [conectar tu CUIT con ARCA](/es/getting-started/index) generamos dos certificados, uno de homologación y otro de producción.

Para pasar a testing, entrá a tu cuenta (tu nombre, abajo en el menú) y en **Entorno** prendé el **Modo Testing**. Es para toda la cuenta: mientras está prendido, todo se factura en el entorno de pruebas de ARCA, sin valor fiscal, incluido lo que llega por tus integraciones y por WhatsApp. Arriba de la pantalla vas a ver el aviso **Modo Testing activo**. Para volver, apagalo.

Las facturas de prueba no cuentan para el límite mensual de tu plan.

---

## Diferencias entre testing y producción

| Aspecto | Testing (Homologación) | Producción |
|---|---|---|
| URL webservice ARCA | wswhomo.afip.gov.ar | servicios1.afip.gov.ar |
| CAE generado | Sin validez fiscal | Válido legalmente |
| CUIT necesario | Tu CUIT real | Tu CUIT real |
| Certificado | Certificado de testing | Certificado de producción |
| API key de Facturear | Key de testing | Key de producción |
| Facturear configura | Automáticamente según el cert | Automáticamente según el cert |

---

## Cómo testear con la API de Facturear

El entorno lo define la **API key** que usás: tu cuenta tiene una key de testing y una de producción (en **Desarrolladores → Claves API**). Con la key de testing, todas las llamadas operan en homologación; el cuerpo de la factura y los endpoints son exactamente los mismos que en producción, así que pasar a producción es solo cambiar la key.

```javascript
const response = await fetch('https://www.facture.ar/api/invoices', {
  method: 'POST',
  headers: {
    'x-api-key': process.env.FACTUREAR_API_KEY_TEST,  // key de testing → homologación
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    cuitId: 'id-de-tu-cuit',      // el mismo CUIT, con su certificado de testing
    invoiceType: 11,              // Factura C
    ptoVta: 1,
    concepto: 1,                  // Productos
    docTipo: 99,                  // Consumidor final sin identificar
    docNro: 0,
    condicionIVAReceptorId: 5,    // Consumidor Final
    clientName: 'Cliente de Prueba',
    impNeto: 1000,
    impTotal: 1000,
    description: 'Producto de prueba'
  })
})

const { batchId } = await response.json()

// Consultá el resultado: en homologación el lote informa "environment": "homologation"
const lote = await fetch(`https://www.facture.ar/api/invoices/batches/${batchId}`, {
  headers: { 'x-api-key': process.env.FACTUREAR_API_KEY_TEST }
}).then(r => r.json())
```

Como en producción, la factura queda **encolada** y el CAE de prueba aparece en el `responseBody` de cada ítem del lote. Ver [Emitir tu primera factura](/es/guides/primera-factura#obtener-el-cae).

## Casos de prueba recomendados

Antes de pasar a producción, testeá al menos estos escenarios:

- Factura C a Consumidor Final (sin datos del receptor)
- Factura A con CUIT de receptor válido
- Factura B con datos del receptor
- Nota de Crédito sobre una factura existente
- Factura con múltiples ítems y alícuotas diferentes
- Error intencional (CUIT receptor inválido) — verificar manejo de errores
- Lote con múltiples facturas
- Lote con algún ítem que falla
- Condición frente al IVA del receptor que no corresponde a la clase (por ejemplo, Factura A con `condicionIVAReceptorId: 5`) — debe responder `400`. Ver [Condición frente al IVA del receptor](/es/guides/condicion-iva-receptor)

## Preguntas frecuentes

<AccordionGroup>
  <Accordion title="¿Las facturas de testing aparecen en mis reportes?">
    Nunca se mezclan con las reales. **Facturas** y **Reportes** muestran solo el entorno en el que está tu cuenta: con el **Modo Testing** prendido ves solo las facturas de prueba, y con el modo apagado, solo las de producción. Por API, `GET /api/invoices` y `GET /api/invoices/stats` devuelven las del entorno de tu API Key.
  </Accordion>
  <Accordion title="¿Puedo usar el mismo CUIT para testing y producción?">
    Sí, pero con diferentes certificados. El CUIT es el mismo; lo que cambia es si usás el certificado de homologación (testing) o el de producción.
  </Accordion>
  <Accordion title="¿El entorno de testing tiene límites de uso?">
    ARCA puede tener límites de velocidad en el entorno de testing, pero son generosos para desarrollo normal. No usés el entorno de testing para cargas de producción.
  </Accordion>
</AccordionGroup>
