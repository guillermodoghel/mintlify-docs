# Integrar Facturear con tu e-commerce

Si tenés una tienda online, podés automatizar completamente la emisión de facturas electrónicas conectando tu plataforma de e-commerce con Facturear. Cada vez que se confirma una venta, la factura se emite automáticamente sin intervención manual.

---

## Beneficios de la integración

- **Automatización total**: factura emitida al segundo del pago confirmado
- **Sin errores manuales**: los datos de la factura vienen directamente de la orden
- **Cumplimiento fiscal garantizado**: toda venta queda facturada con CAE
- **Mejor experiencia del cliente**: recibe la factura por email automáticamente

---

## Opciones de integración

### Opción 1: API REST directa

La forma más flexible. Tu plataforma de e-commerce llama a la API de Facturear cuando se confirma cada venta.

**Flujo típico:**

```javascript
const CLASE_A = [1, 6, 13, 16]  // condiciones frente al IVA que reciben Factura A

// Webhook handler para nueva venta confirmada
app.post('/webhook/nueva-venta', async (req, res) => {
  const orden = req.body
  const cliente = orden.cliente

  // Condición frente al IVA del receptor (ids de ARCA): 5 Consumidor Final si no la informó
  const condicion = Number(cliente.condicionIVAReceptorId) || 5
  const conCuit = Boolean(cliente.cuit)

  // Determinar tipo de factura según el cliente (emisor Responsable Inscripto)
  const invoiceType = conCuit && CLASE_A.includes(condicion)
    ? 1    // Factura A
    : 6    // Factura B (default para consumidores)

  // Los precios de la tienda incluyen IVA 21%: separar neto e IVA
  const total = orden.productos.reduce((acc, p) => acc + p.cantidad * p.precioUnitario, 0)
  const neto = Math.round((total / 1.21) * 100) / 100
  const iva = Math.round((total - neto) * 100) / 100

  // Emitir factura en Facturear (queda encolada)
  const respuesta = await fetch('https://www.facture.ar/api/invoices', {
    method: 'POST',
    headers: {
      'x-api-key': process.env.FACTUREAR_API_KEY,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      cuitId: process.env.FACTUREAR_CUIT_ID,
      invoiceType,
      ptoVta: 1,
      concepto: 1,                                   // Productos
      docTipo: conCuit ? 80 : 99,
      docNro: conCuit ? Number(cliente.cuit.replace(/-/g, '')) : 0,
      condicionIVAReceptorId: condicion,
      clientName: cliente.nombre || 'Consumidor Final',
      impNeto: neto,
      impIVA: iva,
      impTotal: total,
      iva: [{ id: 5, baseImp: neto, importe: iva }],
      description: `Orden #${orden.id}`,
      items: orden.productos.map(p => {
        const unitarioNeto = Math.round((p.precioUnitario / 1.21) * 100) / 100
        return {
          description: p.nombre,
          quantity: p.cantidad,
          unitPrice: unitarioNeto,
          discount: 0,
          ivaRate: 21,
          subtotal: Math.round(unitarioNeto * p.cantidad * 100) / 100
        }
      })
    })
  })

  const resultado = await respuesta.json()
  if (!respuesta.ok) {
    throw new Error(`${resultado.error}: ${JSON.stringify(resultado.details)}`)
  }

  // Guardar el batchId en la orden: el CAE llega después
  await actualizarOrden(orden.id, { facturearBatchId: resultado.batchId })

  res.json({ ok: true })
})
```

La API encola la factura y responde enseguida con un `batchId`, sin CAE. Para completar la orden con el CAE, el número de comprobante y el PDF, consultá el lote en `GET https://www.facture.ar/api/invoices/batches/{batchId}` o suscribite a `invoice.completed`/`invoice.failed` con [webhooks](/es/guides/webhook-integracion): `invoice.completed` trae el CAE, el número y el `invoice.id`. Con el `invoiceId` del resultado descargás el PDF en `GET https://www.facture.ar/api/invoices/{invoiceId}/pdf`.

<Note>
  Si el cliente informa un CUIT y no mandás `condicionIVAReceptorId`, Facturear la toma del padrón de ARCA. Si no corresponde a la clase del comprobante, la API responde `400`. Ver [Condición frente al IVA del receptor](/es/guides/condicion-iva-receptor).
</Note>

### Opción 2: Tiendanube

Para tiendas en Tiendanube, podés usar la API de Tiendanube en combinación con webhooks:

1. Configurá un webhook en Tiendanube para el evento "Pago aprobado"
2. Tu servidor recibe el webhook con los datos de la orden
3. Llamá a la API de Facturear para emitir la factura
4. Guardá el resultado en los metadatos de la orden

### Opción 3: WooCommerce (WordPress)

Para WooCommerce, podés desarrollar un plugin que:
1. Se enganche al hook `woocommerce_payment_complete`
2. Llame a la API de Facturear con los datos del pedido
3. Guarde el número de factura en el pedido

### Opción 4: Shopify

Similar a Tiendanube, usando los webhooks de Shopify para el evento `orders/paid`.

## Manejo de datos del cliente para determinar la factura

Una buena integración de e-commerce le pide al cliente sus datos fiscales al hacer el checkout:

```html
<!-- Formulario de checkout - datos fiscales opcionales -->
<div class="datos-fiscales">
  <h4>Datos para factura (opcional)</h4>
  
  <label>Condición frente al IVA:</label>
  <!-- Los valores son los ids de ARCA para condicionIVAReceptorId -->
  <select name="condicion_iva">
    <option value="5">Consumidor Final</option>
    <option value="1">Responsable Inscripto</option>
    <option value="6">Monotributista</option>
    <option value="4">Exento</option>
  </select>
  
  <!-- Se muestra solo si selecciona Responsable Inscripto, Monotributista o Exento -->
  <div id="datos-empresa" style="display:none">
    <label>CUIT:</label>
    <input type="text" name="cuit" placeholder="XX-XXXXXXXX-X">
    <label>Razón Social:</label>
    <input type="text" name="razon_social">
  </div>
</div>
```

## Manejo de errores en producción

Las integraciones de e-commerce deben manejar los casos donde la facturación falla. Hay dos momentos: la API puede rechazar el pedido al enviarlo (`400` con `error` y `details` si los datos no son válidos, `403` con `SUBSCRIPTION_LIMIT_EXCEEDED` si superaste el límite del plan), o ARCA puede rechazar el comprobante cuando se procesa (el ítem del lote queda en `status: "error"`).

```javascript
try {
  const factura = await emitirFactura(orden)
} catch (error) {
  // Log del error
  console.error('Error al emitir factura:', error)
  
  // Guardar la orden en cola para reintentar
  await encolarParaReintentar(orden.id, error)
  
  // Notificar al equipo (Slack, email, etc.)
  await notificarError(error, orden)
  
  // La venta igual fue exitosa — no bloquear al cliente
  res.json({ ok: true, advertencia: 'Factura pendiente de emisión' })
}
```
