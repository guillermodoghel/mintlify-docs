# Configurar defaults por CUIT en Facturear

La **API de Facturear** permite configurar valores predeterminados para cada CUIT, de modo que no tengas que enviar todos los parámetros en cada llamada de facturación. Esta funcionalidad simplifica la integración para casos de uso repetitivos.

---

## ¿Para qué sirven los defaults?

Si tu integración siempre emite el mismo tipo de factura desde el mismo punto de venta, podés configurar esos valores como default:

- **Tipo de comprobante** (Factura A, B, C, etc.)
- **Punto de venta** predeterminado
- **Concepto** por defecto (Productos, Servicios, Productos y Servicios)
- **Alícuota de IVA** por defecto (la que aparece preseleccionada en los formularios del dashboard)

Además, podés marcar uno de tus CUITs como **CUIT por defecto**: es el que se usa cuando una factura no trae `cuitId` ni `cuit`.

---

## Cómo configurar defaults vía API

Cada default se configura con su propio endpoint, usando el **id del CUIT en Facturear** (lo obtenés con `GET https://www.facture.ar/api/cuits`). Todos son `POST` y reciben un número:

| Endpoint | Body | Qué configura |
|---|---|---|
| `POST /api/cuits/{id}/default-pos` | `{ "defaultPos": 1 }` | Punto de venta |
| `POST /api/cuits/{id}/default-invoice-type` | `{ "defaultInvoiceType": 11 }` | Tipo de comprobante (código de ARCA) |
| `POST /api/cuits/{id}/default-concept` | `{ "defaultConcept": 2 }` | Concepto |
| `POST /api/cuits/{id}/default-iva` | `{ "defaultIva": 5 }` | Alícuota de IVA (código de ARCA) |
| `POST /api/cuits/{id}/set-default` | sin body | Marca este CUIT como el default de tu cuenta |

```bash
curl -X POST https://www.facture.ar/api/cuits/cmg0a1b2c0000abc/default-pos \
  -H "x-api-key: tu_api_key" \
  -H "Content-Type: application/json" \
  -d '{ "defaultPos": 1 }'
```

### Respuesta exitosa

```json
{
  "message": "Default point of sale updated successfully"
}
```

`default-invoice-type` y `default-concept` responden igual, con su propio mensaje. `default-iva` devuelve el CUIT actualizado y `set-default` devuelve `{ "success": true }`. Si el CUIT no existe o no es tuyo, la respuesta es `404`; si el valor no es un número válido, `400`.

<Tip>
  `set-default` acepta en `{id}` tanto el id del CUIT en Facturear como su número (`20123456789`).
</Tip>

También podés configurarlos desde el dashboard, en **CUITs** → tu CUIT, en las pestañas **Puntos de Venta**, **Conceptos**, **Tipos de Comprobante** e **IVA**.

---

## Cómo ver los defaults actuales

### GET /api/cuits/{id}

```bash
curl https://www.facture.ar/api/cuits/cmg0a1b2c0000abc \
  -H "x-api-key: tu_api_key"
```

Los defaults vienen en estos campos del CUIT:

```json
{
  "id": "cmg0a1b2c0000abc",
  "number": "20123456789",
  "default_pos": 1,
  "default_invoice_type": 11,
  "default_concept": 2,
  "default_iva": 5,
  "is_default": true
}
```

---

## Parámetros configurables

| Parámetro | Tipo | Descripción |
|---|---|---|
| `defaultPos` | integer | Número de punto de venta (mayor o igual a 1) |
| `defaultInvoiceType` | integer | Código de ARCA: `1` Factura A, `6` Factura B, `11` Factura C, etc. |
| `defaultConcept` | integer | `1` = Productos, `2` = Servicios, `3` = Ambos |
| `defaultIva` | integer | Código de alícuota de ARCA: `3` = 0%, `4` = 10,5%, `5` = 21%, `6` = 27% |

Los códigos vigentes están en la [API de parámetros de ARCA](/es/guides/parametros-arca).

<Note>
  El default de IVA lo usan los formularios del dashboard. La API no calcula el IVA a partir de él: en cada factura mandá el detalle en `iva` y los importes (`impNeto`, `impIVA`, `impTotal`). La moneda no tiene default configurable: si no mandás `monId`, la factura sale en pesos (`PES`).
</Note>

## Sobrescribir defaults en una factura específica

Los defaults son solo valores predeterminados. Podés sobrescribirlos en cualquier factura individual incluyendo el campo en la request:

```json
{
  "concepto": 1,
  "impTotal": 50000
}
```

Si enviás `concepto: 1` en la request, ese valor se usa en lugar del default configurado. Lo mismo vale para `ptoVta` e `invoiceType`.

---

## Defaults y múltiples puntos de venta

Si tu empresa tiene múltiples puntos de venta, podés:

1. Configurar un punto de venta como default
2. Sobreescribirlo con `ptoVta` en las facturas que correspondan a otro punto de venta

O alternativamente, no configurar un default de punto de venta y enviar `ptoVta` explícitamente en cada request. Si el CUIT no tiene punto de venta por defecto y la factura no trae `ptoVta`, la API responde `400`. Lo mismo pasa con el concepto.

## Ejemplo: configuración para monotributista simple

```bash
# Punto de venta 1, Factura C, servicios
curl -X POST https://www.facture.ar/api/cuits/cmg0a1b2c0000abc/default-pos \
  -H "x-api-key: tu_api_key" -H "Content-Type: application/json" \
  -d '{ "defaultPos": 1 }'

curl -X POST https://www.facture.ar/api/cuits/cmg0a1b2c0000abc/default-invoice-type \
  -H "x-api-key: tu_api_key" -H "Content-Type: application/json" \
  -d '{ "defaultInvoiceType": 11 }'

curl -X POST https://www.facture.ar/api/cuits/cmg0a1b2c0000abc/default-concept \
  -H "x-api-key: tu_api_key" -H "Content-Type: application/json" \
  -d '{ "defaultConcept": 2 }'

curl -X POST https://www.facture.ar/api/cuits/cmg0a1b2c0000abc/set-default \
  -H "x-api-key: tu_api_key"
```

Con esta configuración, una request mínima de facturación (una Factura C de servicios a consumidor final) sería:

```json
{
  "condicionIVAReceptorId": 5,
  "impNeto": 50000,
  "impTotal": 50000,
  "fchServDesde": "20260901",
  "fchServHasta": "20260930",
  "fchVtoPago": "20261010",
  "description": "Servicio de consultoría",
  "items": [
    {
      "description": "Servicio de consultoría",
      "quantity": 1,
      "unitPrice": 50000,
      "discount": 0,
      "ivaRate": 0,
      "subtotal": 50000
    }
  ]
}
```

El CUIT, el punto de venta, el tipo de comprobante y el concepto salen de los defaults, y el receptor queda como consumidor final sin identificar (`docTipo` 99). Para facturarle a un cliente con CUIT, agregá `docTipo: 80`, `docNro` y `clientName`. Ver [Primera factura con Facturear](/es/guides/primera-factura).
