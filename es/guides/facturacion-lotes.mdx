# Facturación masiva en lotes

La **facturación en lotes** te permite emitir múltiples facturas electrónicas en una sola operación asincrónica. Es ideal para e-commerce, facturación mensual recurrente, sistemas ERP y cualquier caso donde necesitás procesar muchas facturas juntas.

---

## Lotes desde el dashboard (CSV)

Si cargás comprobantes con **archivo CSV** desde la web (sin armar integración propia), el flujo, las columnas y el archivo de ejemplo están detallados en **[Facturación por lotes desde la app](/es/funcionalidades/facturacion-por-lotes)**. Incluye la columna opcional **`cbte_fch`**, correlatividad de fechas dentro del lote y contra ARCA.

En el dashboard, el lote sale siempre del **CUIT activo** (el que elegiste en el selector del header): el CSV ya no lleva columna de CUIT emisor. El CSV también acepta una columna **`email`** (o `mail`/`correo`): cada factura se manda sola a esa dirección apenas ARCA la autoriza.

Por API no hay CUIT activo: cada ítem indica su emisor con `cuitId` o `cuit` y, si no mandás ninguno, se usa el CUIT por defecto de la cuenta.

---

## Fecha del comprobante (`cbteFch`) en la API

En cada ítem que envíes al batch (mismo cuerpo que una factura suelta en `/api/invoices`), podés incluir el campo opcional **`cbteFch`** en formato **`YYYYMMDD`**. Si no lo enviás, Facturear usa la **fecha actual** al ejecutar el trabajo contra ARCA.

Reglas que aplican igual que en ARCA:

- Por **CUIT + punto de venta + tipo de comprobante**, la fecha del nuevo comprobante **no puede ser menor** que la del último comprobante autorizado en ese circuito.
- **Orden dentro del lote**: para el mismo circuito, las fechas efectivas deben ser **no decrecientes** en el orden en que se procesan los ítems.

Para facturación retroactiva (por ejemplo cerrar un mes anterior), solo es coherente si **no emitiste** después con fechas más nuevas en ese mismo punto de venta y tipo.

---

## ¿Cuándo usar lotes?

| Caso de uso | Sin lotes | Con lotes |
|---|---|---|
| Emitir 500 facturas fin de mes | 500 requests individuales | 1 batch con 500 items |
| E-commerce con picos de ventas | Posibles timeouts | Procesamiento asincrónico |
| Facturación recurrente SaaS | Script secuencial lento | Procesamiento paralelo |
| Migración de facturas históricas | Inviable | Ideal |

<Info>
  Los lotes procesan las facturas de forma **asincrónica**. Enviás el lote, Facturear lo procesa con ARCA y podés consultar el estado cuando quieras. No necesitás esperar a que termine para continuar con otras operaciones.
</Info>

---

## Flujo de trabajo con lotes

<Steps>
  **Crear el lote**: `POST /api/invoices` con un **array** de facturas (hasta 500) — el lote se crea y se encola en una sola llamada

  **Agregar facturas** (opcional): `PATCH /api/invoices/batches/{batchId}` con otro array, mientras el lote no haya terminado

  **Procesar**: Facturear procesa cada factura con ARCA automáticamente

  **Consultar estado**: `GET /api/invoices/batches/{batchId}` — verificá el progreso y el CAE de cada ítem

  **Manejar errores**: reintentá los ítems fallidos con `POST /api/invoices/batches/{batchId}/items/{itemId}/retry`
</Steps>

## Crear un lote

```bash
POST https://www.facture.ar/api/invoices
```

El cuerpo es un array donde cada elemento tiene **el mismo formato que una factura suelta** (ver [Emitir tu primera factura](/es/guides/primera-factura)). Cada ítem puede tener su propio `cuitId`, tipo de comprobante, receptor e importes, y un `emailTo` opcional (hasta 5 direcciones) para que el PDF se mande solo cuando ARCA la autoriza:

```javascript
const facturas = [
  {
    cuitId: 'id-de-tu-cuit',
    invoiceType: 1,               // Factura A
    ptoVta: 1,
    concepto: 2,
    docTipo: 80,
    docNro: 30711111111,
    condicionIVAReceptorId: 1,    // IVA Responsable Inscripto
    clientName: 'Cliente Uno S.A.',
    cbteFch: '20260930',          // opcional, YYYYMMDD; si omitís, fecha del día al procesar
    fchServDesde: '20260901',
    fchServHasta: '20260930',
    fchVtoPago: '20261010',
    impNeto: 25000,
    impIVA: 5250,
    impTotal: 30250,
    iva: [{ id: 5, baseImp: 25000, importe: 5250 }],
    description: 'Suscripción Pro - Septiembre 2026',
    emailTo: ['facturacion@clienteuno.com.ar']  // opcional: se manda el PDF cuando ARCA la autoriza
  },
  {
    cuitId: 'id-de-tu-cuit',
    invoiceType: 6,               // Factura B
    ptoVta: 1,
    concepto: 2,
    docTipo: 99,                  // Consumidor final sin identificar
    docNro: 0,
    condicionIVAReceptorId: 5,    // Consumidor Final
    fchServDesde: '20260901',
    fchServHasta: '20260930',
    fchVtoPago: '20261010',
    impNeto: 8000,
    impIVA: 1680,
    impTotal: 9680,
    iva: [{ id: 5, baseImp: 8000, importe: 1680 }],
    description: 'Suscripción Basic - Septiembre 2026'
  }
  // ... más facturas (hasta 500 por request)
]

const response = await fetch('https://www.facture.ar/api/invoices', {
  method: 'POST',
  headers: {
    'x-api-key': 'tu_api_key',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify(facturas)
})

const lote = await response.json()
console.log('Batch ID:', lote.batchId)
```

Respuesta:

```json
{
  "batch": true,
  "message": "Lote de facturas encolado para procesamiento",
  "count": 2,
  "status": "processing",
  "batchId": "cmg1a2b3c0000xyz",
  "queueIdentifiers": ["..."]
}
```

Antes de encolar, Facturear valida **todos** los ítems. Si alguno tiene datos inválidos, la API responde `400` con `{ "error": "Datos inválidos en el lote", "details": [...] }` y no encola ninguno.

## Agregar facturas al lote

```bash
PATCH https://www.facture.ar/api/invoices/batches/{batchId}
```

El cuerpo es directamente un array de facturas, con el mismo formato que al crear el lote (hasta 500 por llamada):

```javascript
await fetch(`https://www.facture.ar/api/invoices/batches/${batchId}`, {
  method: 'PATCH',
  headers: {
    'x-api-key': 'tu_api_key',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify(masFacturas)
})
```

<Tip>
  Mandá un header `Idempotency-Key` en cada `POST` o `PATCH` de lote: si la llamada se corta y la reenviás con la misma clave, recibís el mismo `batchId` y ninguna factura se duplica. Cada ítem queda identificado como `<clave>:<posición>`. Ver [Reintentar sin duplicar facturas](/es/guides/idempotencia).
</Tip>

<Info>
  Podés agregar facturas en múltiples llamadas al mismo lote mientras no haya terminado. Si el lote ya está en `completed`, `completed_with_errors` o `error`, la API responde `400`: en ese caso creá un lote nuevo con `POST /api/invoices`.
</Info>

## Consultar el estado del lote

```bash
GET https://www.facture.ar/api/invoices/batches/{batchId}
```

```javascript
const batch = await fetch(`https://www.facture.ar/api/invoices/batches/${batchId}`, {
  headers: { 'x-api-key': 'tu_api_key' }
}).then(r => r.json())

console.log(`Total: ${batch.totalItems}`)
console.log(`Procesados: ${batch.processedItems}`)
console.log(`Exitosos: ${batch.successfulItems}`)
console.log(`Fallidos: ${batch.failedItems}`)
```

            "FECAEDetResponse": [
              { "Resultado": "A", "CAE": "76123456789012", "CAEFchVto": "20261010" }

El `status` del lote pasa por `pending` y `processing` y termina en `completed`, `completed_with_errors` o `error`. Cada ítem queda en `completed` (con el CAE en `responseBody`) o en `error` (con los mensajes de ARCA o de validación).

## Manejar errores y reintentos

Los ítems en estado `error` se pueden reintentar individualmente:

```bash
POST https://www.facture.ar/api/invoices/batches/{batchId}/items/{itemId}/retry
```

```javascript
await fetch(
  `https://www.facture.ar/api/invoices/batches/${batchId}/items/${itemId}/retry`,
  {
    method: 'POST',
    headers: { 'x-api-key': 'tu_api_key' }
  }
)
```

El reintento vuelve a encolar el ítem **con los mismos datos**: sirve para errores transitorios (ARCA caído, timeouts, un certificado que ya corregiste). Cada ítem admite hasta 5 reintentos manuales.

Si el error está en los datos (por ejemplo, un CUIT de receptor equivocado), emití una factura nueva con los datos corregidos con `POST /api/invoices` y un `Idempotency-Key` nuevo. Si el ítem falló con `errorCategory: "ARCA_OUTCOME_UNKNOWN"` (ARCA no respondió y la factura puede estar autorizada), no la emitas de nuevo: reintentá el ítem, que consulta a ARCA antes de volver a emitir.

## Listar todos los lotes

```bash
GET https://www.facture.ar/api/invoices/batches
```

```javascript
const { batches, pagination } = await fetch('https://www.facture.ar/api/invoices/batches?page=1&limit=20', {
  headers: { 'x-api-key': 'tu_api_key' }
}).then(r => r.json())
```

Parámetros disponibles:
- `page` / `limit`: paginación (máximo 100 por página)

La lista incluye los lotes del entorno de tu API key (producción u homologación).

## Ejemplo completo: facturación mensual de un SaaS

Este script procesa todos los clientes activos de un SaaS y emite una factura mensual para cada uno, en lotes de hasta 500:

```javascript
const BASE_URL = 'https://www.facture.ar/api'
const CLASE_A = [1, 6, 13, 16]  // condiciones frente al IVA que reciben Factura A

function armarFactura(cliente, mes, cuitId) {
  const neto = cliente.montoPlan
  const iva = Math.round(neto * 0.21 * 100) / 100
  const conCuit = Boolean(cliente.cuit)
  // cliente.condicionIVAReceptorId: 1 RI, 4 Exento, 5 Consumidor Final, 6 Monotributo...
  const condicion = cliente.condicionIVAReceptorId ?? 5

  return {
    cuitId,
    invoiceType: conCuit && CLASE_A.includes(condicion) ? 1 : 6,  // A o B
    ptoVta: 1,
    concepto: 2,
    docTipo: conCuit ? 80 : 99,
    docNro: conCuit ? Number(cliente.cuit.replace(/-/g, '')) : 0,
    condicionIVAReceptorId: condicion,
    clientName: cliente.razonSocial,
    fchServDesde: mes.desde,       // 'YYYYMMDD'
    fchServHasta: mes.hasta,
    fchVtoPago: mes.vencimiento,
    impNeto: neto,
    impIVA: iva,
    impTotal: Math.round((neto + iva) * 100) / 100,
    iva: [{ id: 5, baseImp: neto, importe: iva }],
    description: `Suscripción ${cliente.plan} - ${mes.nombre}`
  }
}

async function facturacionMensual(clientes, mes) {
  const apiKey = process.env.FACTUREAR_API_KEY
  const cuitId = process.env.FACTUREAR_CUIT_ID
  const headers = { 'x-api-key': apiKey, 'Content-Type': 'application/json' }

  // 1. Crear un lote por cada bloque de hasta 500 facturas
  const CHUNK_SIZE = 500
  const batchIds = []
  for (let i = 0; i < clientes.length; i += CHUNK_SIZE) {
    const facturas = clientes.slice(i, i + CHUNK_SIZE).map(c => armarFactura(c, mes, cuitId))

    const res = await fetch(`${BASE_URL}/invoices`, {
      method: 'POST',
      headers,
      body: JSON.stringify(facturas)
    })
    const body = await res.json()
    if (!res.ok) throw new Error(`${body.error}: ${JSON.stringify(body.details)}`)

    batchIds.push(body.batchId)
    console.log(`Lote creado: ${body.batchId} (${body.count} facturas)`)
  }

  // 2. Polling hasta que cada lote termine
  const TERMINADO = ['completed', 'completed_with_errors', 'error']
  const resultados = []
  for (const batchId of batchIds) {
    let batch
    do {
      await new Promise(r => setTimeout(r, 5000))  // Esperar 5 segundos
      batch = await fetch(`${BASE_URL}/invoices/batches/${batchId}`, { headers }).then(r => r.json())
      console.log(`${batchId}: ${batch.processedItems}/${batch.totalItems}`)
    } while (!TERMINADO.includes(batch.status))

    console.log(`Exitosos: ${batch.successfulItems}, Fallidos: ${batch.failedItems}`)
    resultados.push(batch)
  }
  return resultados
}
```

## Límites y consideraciones

| Parámetro | Límite |
|---|---|
| Facturas por request (`POST /api/invoices` o `PATCH`) | 500 |
| Reintentos manuales por ítem | 5 |
| Facturas por período | Según tu plan (si lo superás, la API responde `403` con `SUBSCRIPTION_LIMIT_EXCEEDED`) |

<Warning>
  Aunque los lotes son asincrónicos, ARCA puede tener límites de tasa. Si procesás volúmenes muy altos, implementá backoff exponencial en los reintentos de errores de ARCA.
</Warning>

## Preguntas frecuentes

<AccordionGroup>
  <Accordion title="¿Puedo cancelar un lote en proceso?">
    No se puede cancelar un lote que ya está siendo procesado. Los ítems que ya obtuvieron CAE están emitidos y son válidos. Si necesitás anularlos, debés emitir Notas de Crédito.
  </Accordion>
  <Accordion title="¿Los errores de ARCA en un ítem afectan al resto del lote?">
    No. Cada ítem del lote se procesa de forma independiente. Si un ítem falla por un error de ARCA (CUIT inválido, etc.), el resto sigue procesándose normalmente y el lote termina en `completed_with_errors`.
  </Accordion>
  <Accordion title="¿Cómo sé cuándo terminó el lote?">
    Consultá el lote con `GET /api/invoices/batches/{batchId}` hasta que el `status` sea `completed`, `completed_with_errors` o `error`, o suscribite a `invoice.completed`/`invoice.failed` (resultado de cada factura) y `batch.completed` (fin del lote) con [webhooks](/es/guides/webhook-integracion).
  </Accordion>
  <Accordion title="¿Puedo agregar ítems a un lote que ya está procesando?">
    Sí, mientras el lote esté en `pending` o `processing` podés seguir agregando facturas con `PATCH /api/invoices/batches/{batchId}`. Los nuevos ítems se encolan y se procesan. Una vez terminado, ya no acepta ítems nuevos.
  </Accordion>
  <Accordion title="¿Puedo enviar la fecha del comprobante (cbteFch / cbte_fch)?">
    Sí: en API usá **`cbteFch`** (`YYYYMMDD`) por ítem; en CSV del dashboard usá la columna **`cbte_fch`** (`YYYYMMDD` o `YYYY-MM-DD`). Si no lo definís, se usa la fecha actual al procesar. ARCA no permite fechas anteriores al último comprobante de ese punto de venta y tipo; dentro del lote, las fechas no pueden ir hacia atrás para el mismo circuito.
  </Accordion>
</AccordionGroup>
