# Webhooks en Facturear

Los **webhooks** te permiten recibir notificaciones en tiempo real cuando ocurren eventos en Facturear, sin necesidad de hacer polling a la API. Tu sistema recibe un POST automático cuando algo sucede.

<Note>
  Hoy Facturear envía un único evento por webhook: `delegation.completed`, cuando termina la delegación de un CUIT. **Todavía no hay webhooks para facturas** (emitidas, rechazadas o lotes terminados). Para saber el resultado de una factura, consultá `GET https://www.facture.ar/api/invoices/batches/{batchId}` con el `batchId` que te devuelve `POST /api/invoices` (ver [Facturación en lotes](/es/guides/facturacion-lotes)).
</Note>

---

## ¿Cómo funcionan los webhooks?

```
ARCA confirma la delegación del CUIT → Facturear la registra → POST a tu URL webhook
```

1. Registrás una URL de tu sistema en Facturear
2. Cuando la delegación de uno de tus CUITs queda completa en un entorno, Facturear hace un HTTP POST a esa URL
3. Tu sistema recibe el evento y actúa (habilita la facturación para ese cliente, le avisa, etc.)

---

## Eventos disponibles

| Evento | Cuándo se dispara |
|---|---|
| `delegation.completed` | La delegación de un CUIT quedó completa en homologación o en producción. Se envía una vez por cada entorno |

---

## Configurar un webhook

Los webhooks se configuran desde el **dashboard**, no con la API key:

1. Iniciá sesión en [facture.ar](https://facture.ar)
2. En el menú lateral, entrá a **Webhooks**
3. Presioná **"Add Webhook"**
4. Completá:
   - **URL**: la dirección de tu sistema que va a recibir el POST
   - **Events**: `delegation.completed`
   - **Headers** (opcional): headers propios que Facturear agrega a cada envío, por ejemplo un token para autenticar el pedido
5. Guardá

Desde la misma pantalla podés editar el webhook, pausarlo y reactivarlo, eliminarlo y ver el historial de envíos.

---

## Payload del evento

Cuando se dispara el evento, Facturear envía un POST con `Content-Type: application/json`, `User-Agent: Facturear-Webhook/1.0` y los headers que configuraste. El body es:

```json
{
  "event": "delegation.completed",
  "cuit": {
    "id": "cmg1a2b3c0000xyz",
    "number": "20123456789",
    "userId": "cmg0z9y8x0000abc"
  },
  "status": {
    "setupStatus": "DELEGATION_COMPLETE",
    "testingSetupState": "COMPLETED",
    "productionSetupState": "COMPLETED"
  },
  "environment": "production",
  "timestamp": "2026-09-28T13:30:00.000Z"
}
```

| Campo | Qué es |
|---|---|
| `event` | Nombre del evento |
| `cuit.id` / `cuit.number` | Id del CUIT en Facturear y su número |
| `status.testingSetupState` / `status.productionSetupState` | Estado de la configuración en cada entorno |
| `status.setupStatus` | Pasa a `DELEGATION_COMPLETE` cuando ambos entornos quedaron completos |
| `environment` | Entorno que se acaba de completar: `homologation` o `production` |
| `timestamp` | Momento del envío, en ISO 8601 |

## Verificar la autenticidad del webhook

Facturear **no firma** los webhooks. Para verificar que el pedido viene de Facturear, configurá un header propio con un valor secreto (por ejemplo `Authorization: Bearer <token>` o `X-Webhook-Token: <token>`) y validalo en tu endpoint:

```javascript
const crypto = require('crypto');

function tokenValido(recibido, esperado) {
  if (typeof recibido !== 'string') return false;
  const a = Buffer.from(recibido);
  const b = Buffer.from(esperado);
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}

// En tu endpoint
app.post('/webhooks/facturear', (req, res) => {
  const token = req.headers['x-webhook-token'];

  if (!tokenValido(token, process.env.FACTUREAR_WEBHOOK_TOKEN)) {
    return res.status(401).json({ error: 'Token inválido' });
  }

  // Procesar el evento
  procesarEvento(req.body);
  res.status(200).json({ received: true });
});
```

## Responder correctamente al webhook

Tu endpoint debe:

1. Responder con **HTTP 2xx** lo antes posible (Facturear corta cada intento a los 10 segundos)
2. Procesar el evento en background si es operación lenta
3. Si respondés con cualquier código que no sea 2xx, o no respondés a tiempo, Facturear reintenta el webhook

```javascript
app.post('/webhooks/facturear', async (req, res) => {
  // Responder primero para evitar timeout
  res.status(200).json({ received: true });

  // Procesar en background
  setImmediate(() => {
    procesarEventoFacturear(req.body).catch(console.error);
  });
});
```

---

## Reintentos de webhooks

Si tu endpoint no responde con 2xx, Facturear reintenta:

| Intento | Delay |
|---|---|
| 1 (original) | Inmediato |
| 2 | 1 segundo |
| 3 | 2 segundos |

Después del 3er intento fallido, el envío queda registrado como fallido.

---

## Consultar webhooks fallidos

Cada envío (exitoso o fallido) queda en el historial del webhook, con el payload, los headers, el código y el body de tu respuesta, y el error si lo hubo. Lo ves desde **Webhooks** en el dashboard, y desde ahí podés **reintentar** un envío fallido.
