# Webhooks en Facturear

Los **webhooks** te permiten recibir notificaciones en tiempo real cuando ocurren eventos en Facturear, sin necesidad de hacer polling a la API. Tu sistema recibe un POST automático cuando algo sucede: una factura obtuvo CAE, ARCA la rechazó, terminó un lote, un borrador leído de un documento espera tu revisión, llegó una comunicación nueva al Domicilio Fiscal Electrónico o cambió el saldo de la cuenta tributaria de un CUIT.

---

## ¿Cómo funcionan los webhooks?

```
ARCA autoriza la factura → Facturear guarda el CAE → POST firmado a tu URL webhook
```

1. Registrás una URL de tu sistema en Facturear y elegís qué eventos querés recibir
2. Cuando ocurre uno de esos eventos, Facturear hace un HTTP POST a esa URL, firmado con el secreto de tu webhook
3. Tu sistema verifica la firma, responde 2xx y actúa (completa la orden con el CAE, avisa al cliente, reintenta con otros datos, etc.)

Los eventos se envían para los dos entornos, homologación y producción: el campo `environment` del payload te dice de cuál viene.

Los eventos disponibles son `invoice.completed`, `invoice.failed`, `batch.completed`, `draft.review_required`, `dfe.message.received` y `tax_account.updated`. Qué dispara cada uno y el payload completo están en la [referencia de webhooks](/es/api-reference/webhooks#eventos). Para seguir facturas emitidas por API, lo habitual es suscribirse a `invoice.completed` e `invoice.failed` (resultado de cada factura) y a `batch.completed` (fin del lote): toda factura emitida por API se procesa en un lote, así que cada una termina en `invoice.completed` o en `invoice.failed`.

## Paso 1: crear el webhook

Desde el dashboard:

1. Iniciá sesión en [facture.ar](https://www.facture.ar/?utm_source=docs&utm_medium=referral&utm_campaign=guides-webhook-integracion&utm_content=link)
2. En el menú lateral, en **Desarrolladores**, entrá a **Webhooks**
3. Presioná **"Agregar webhook"**
4. Completá:
   - **URL del webhook**: la dirección de tu sistema que va a recibir el POST (`https` y pública)
   - **Eventos**: marcá los eventos que te interesan
   - **Headers** (opcional): headers propios que Facturear agrega a cada envío
5. Presioná **"Crear"**. Facturear genera el **secreto de firma** del webhook (empieza con `whsec_`)

En la lista de webhooks, cada uno tiene estas acciones:

- **Secreto de firma**: muestra el secreto, con **Copiar** y **Rotar**
- **Ver entregas**: el historial de envíos, con el detalle de cada uno y **Reintentar**
- **Editar** y **Eliminar**
- El estado (**Activo** / **Inactivo**): hacé clic para pausarlo o reactivarlo

También podés crearlo con tu API Key de producción (`POST /api/webhooks` con `url` y `events`): la respuesta trae el secreto (`secret`), y es la única vez que la API lo devuelve. Los endpoints para listar, editar y borrar están en [Crear y administrar webhooks](/es/api-reference/webhooks#crear-y-administrar-webhooks).

<Warning>
  Guardá el secreto como cualquier otra credencial (variable de entorno, gestor de secretos). Si se filtra, rotalo: desde ese momento los envíos se firman con el secreto nuevo y el anterior deja de validar, así que actualizalo en tu sistema enseguida.
</Warning>

## Paso 2: recibir y verificar la firma

Cada envío trae el header `Facturear-Signature: t=<segundos unix>,v1=<firma hex>`, donde `v1` es el HMAC-SHA256 de `<t>.<body crudo>` con tu secreto (completo, con `whsec_`). Tu endpoint tiene que verificarla antes de hacerle caso: calculá la firma sobre el body **crudo**, comparala con cada `v1` en tiempo constante y rechazá el envío si `t` está a más de 300 segundos de tu reloj. El detalle, los demás headers y el ejemplo en Python están en [Verificar la firma](/es/api-reference/webhooks#verificar-la-firma).

<Warning>
  Firmá sobre el body crudo, no sobre el JSON ya parseado: si tu framework parsea el body y lo volvés a serializar, cambian espacios u orden de claves y la firma no coincide.
</Warning>

### Ejemplo en Node.js (Express)

```javascript
const crypto = require('crypto');
const express = require('express');

const app = express();
const TOLERANCIA_SEGUNDOS = 300;

function verificarFirma(secreto, bodyCrudo, header) {
  if (!header) return false;
  let t = null;
  const firmas = [];
  for (const parte of header.split(',')) {
    const [clave, valor] = parte.trim().split('=', 2);
    if (clave === 't' && valor && /^\d+$/.test(valor)) t = Number(valor);
    if (clave === 'v1' && valor) firmas.push(valor);
  }
  if (t === null || firmas.length === 0) return false;

  const esperada = Buffer.from(crypto.createHmac('sha256', secreto).update(`${t}.${bodyCrudo}`, 'utf8').digest('hex'), 'hex');
  const coincide = firmas.some(firma => {
    const recibida = Buffer.from(firma, 'hex');
    return recibida.length === esperada.length && crypto.timingSafeEqual(recibida, esperada);
  });
  if (!coincide) return false;

  return Math.abs(Math.floor(Date.now() / 1000) - t) <= TOLERANCIA_SEGUNDOS;
}

// express.raw deja el body sin parsear, que es lo que se firmó
app.post('/webhooks/facturear', express.raw({ type: 'application/json' }), (req, res) => {
  const bodyCrudo = req.body.toString('utf8');

  if (!verificarFirma(process.env.FACTUREAR_WEBHOOK_SECRET, bodyCrudo, req.get('Facturear-Signature'))) {
    return res.status(400).json({ error: 'Firma inválida' });
  }

  const evento = JSON.parse(bodyCrudo);
  res.status(200).json({ received: true });

  setImmediate(() => procesarEvento(evento).catch(console.error));
});
```

Si además configuraste un header propio con un token, podés validarlo también; la firma ya cubre la autenticidad del pedido.

## Paso 3: responder y procesar

Tu endpoint debe:

1. Responder con **HTTP 2xx** dentro de los **10 segundos**. Un `3xx` cuenta como falla (las redirecciones no se siguen), así que registrá la URL final
2. Procesar el evento en background si es una operación lenta
3. Ser **idempotente**: guardá el `id` del body de los eventos que ya procesaste e ignorá los repetidos. El `id` es el mismo en los reintentos automáticos y en los manuales; el header `Facturear-Delivery`, en cambio, cambia en cada reintento manual

Si no respondés 2xx a tiempo, Facturear reintenta: hasta **3 intentos** en total (esperando 1 y 2 segundos entre uno y otro). Después la entrega queda como fallida y no se reintenta sola; la podés reintentar desde **Ver entregas** en el dashboard. El detalle está en [Entregas y reintentos](/es/api-reference/webhooks#entregas-y-reintentos). Para no perder resultados de facturas si tu endpoint estuvo caído, conciliá de vez en cuando con `GET /api/invoices/batches/{batchId}`.

### Qué hacer con cada evento

- `invoice.completed`: guardá `invoice.cae` y `invoice.voucherNumber` en tu orden; con `invoice.id` bajás el PDF en `GET /api/invoices/{invoiceId}/pdf`
- `invoice.failed`: el motivo está en `errors` y `observations`. Corregí los datos y emitila con una `Idempotency-Key` nueva (ver [idempotencia](/es/guides/idempotencia)). Si ARCA no respondió y el comprobante puede estar autorizado, no llega `invoice.failed`: Facturear reintenta el ítem solo
- `batch.completed`: el detalle de cada ítem está en `GET /api/invoices/batches/{batchId}`

Los payloads completos están en la [referencia de webhooks](/es/api-reference/webhooks#payload).
