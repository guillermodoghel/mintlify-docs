# Cómo emitir tu primera factura electrónica con Facturear

Una vez que tu CUIT está conectado con ARCA, estás listo para emitir tu primera factura electrónica. Esta guía cubre los dos caminos: desde el **dashboard** y via **API**.

---

## Antes de empezar

Asegurate de tener completado:

- ✅ [Cuenta activa en Facturear](https://facture.ar)
- ✅ [CUIT conectado con ARCA](/es/getting-started) (el agente de trámites deja listos los certificados y el punto de venta)

Si no completaste alguno de estos pasos, seguí primero la [guía de inicio](/es/getting-started).

---

## Opción 1: Emitir desde el Dashboard

### Paso 1: Nueva factura

1. Iniciá sesión en [facture.ar](https://facture.ar)
2. En el menú lateral, hacé clic en **"Facturas"**
3. Presioná el botón **"Nueva Factura"**

### Paso 2: Datos del comprobante

Completá los campos principales:

**Tipo de comprobante**

| Si sos... | Y tu cliente es... | Elegí... |
|---|---|---|
| Responsable Inscripto | Responsable Inscripto | Factura A |
| Responsable Inscripto | Consumidor Final / Monotributista | Factura B |
| Monotributista | Cualquier cliente | Factura C |

Ver la guía completa de [tipos de comprobantes](/es/fundamentos/tipos-de-comprobantes) si tenés dudas.

**Punto de venta**: seleccioná el punto de venta que configuraste en ARCA.

**Fecha**: por defecto es la fecha actual. En algunos casos podés retroactuar (consultá los límites en la normativa vigente).

### Paso 3: Datos del receptor

Según el tipo de comprobante y el monto:

- **Factura A**: CUIT obligatorio + razón social
- **Factura B/C por menos de $10.000.000**: podés dejar "Consumidor Final" sin identificar
- **Factura B/C de $10.000.000 o más**: el comprador tiene que quedar identificado con DNI, CUIL o CDI (o pasaporte si es extranjero). Lo exige la RG 1415 (texto RG 5866/2026) y Facturear rechaza la factura antes de pedir el CAE si falta
- **CUIT del consumidor final**: sin importar el monto, si el comprador lo pide para deducir el gasto en Ganancias

Facturear valida el CUIT en tiempo real contra la base de ARCA.

### Paso 4: Detalle de la factura

Agregá uno o más ítems:

1. Hacé clic en **"Agregar ítem"**
2. Completá:
   - Descripción del producto/servicio
   - Cantidad
   - Precio unitario
   - Alícuota de IVA (solo para Facturas A y B)
3. Repetí para cada ítem

Facturear calcula automáticamente:
- Subtotal neto
- IVA por alícuota
- Total

### Paso 5: Emitir

1. Revisá el resumen de la factura
2. Hacé clic en **"Emitir Factura"**
3. Facturear envía los datos a ARCA y espera la respuesta

En segundos, tu factura tendrá:
- **CAE** (Código de Autorización Electrónico)
- **Fecha de vencimiento del CAE**
- **PDF listo para descargar o enviar**

### Paso 6: Entregar al cliente

Desde la pantalla de confirmación podés:
- **Descargar PDF** para enviar por tu cuenta
- **Enviar por email** directamente desde Facturear
- **Compartir link** de descarga

## Opción 2: Emitir via API

La API de Facturear es RESTful y su URL base es `https://www.facture.ar/api`. Para emitir una factura necesitás:

### Autenticación

Incluí tu API key en el header de cada request:

```
x-api-key: tu_api_key_aqui
Content-Type: application/json
```

Encontrá tu API key en **Configuración → API** en el dashboard de Facturear. La key de testing opera en [homologación](/es/guides/entorno-testing) (sin validez fiscal) y la de producción emite comprobantes reales.

### Cómo es el cuerpo de una factura

`POST /api/invoices` recibe **un objeto** (una factura) o **un array de hasta 500 objetos** (un lote). Todos los campos van en el primer nivel, con los nombres que usa ARCA:

| Campo | Qué es |
|---|---|
| `cuitId` o `cuit` | CUIT emisor: el id del CUIT en Facturear o el número (`"20-12345678-9"`). Si no mandás ninguno, se usa tu CUIT por defecto |
| `invoiceType` | Tipo de comprobante de ARCA: `1` Factura A, `6` Factura B, `11` Factura C, etc. (`51`, la ex Factura M, se imprime como "A" con leyenda desde la RG 5762/2025). Si no lo mandás, se usa el default del CUIT |
| `ptoVta` | Punto de venta. Default: el del CUIT |
| `concepto` | `1` productos, `2` servicios, `3` ambos. Default: el del CUIT |
| `docTipo` / `docNro` | Documento del receptor: `80` CUIT, `86` CUIL, `96` DNI, `99` consumidor final sin identificar (default `99` y `0`) |
| `condicionIVAReceptorId` | Condición frente al IVA del receptor. Ver [Condición frente al IVA del receptor](/es/guides/condicion-iva-receptor) |
| `impTotal`, `impNeto`, `impIVA` | Total, neto gravado e IVA. `impTotal` es obligatorio |
| `iva` | Detalle de IVA por alícuota: `{ id, baseImp, importe }` (`5` = 21%, `4` = 10,5%, `6` = 27%, `3` = 0%) |
| `fchServDesde`, `fchServHasta`, `fchVtoPago` | Obligatorios para servicios (`concepto` 2 o 3), en formato `YYYYMMDD` |
| `clientName`, `clientAddress` | Nombre o razón social y domicilio del receptor, impresos en la factura. `clientName` es obligatorio en la práctica para una Factura A; si el receptor tiene CUIT y no lo mandás, se toma del padrón |
| `condicionVenta` | Condición de venta impresa en la factura: `contado`, `cuenta_corriente`, `tarjeta_debito`, `tarjeta_credito`, `transferencia`, `cheque` u `otra`. ARCA no la recibe: es un dato del comprobante impreso |
| `description`, `items` | Descripción y detalle de ítems que se muestran en el PDF |

Los importes tienen que cerrar: `impTotal = impNeto + impIVA + impTrib + impTotConc + impOpEx`.

### Emitir una Factura C (Monotributista)

Una Factura C a consumidor final no discrimina IVA: el neto es igual al total.

```bash
curl -X POST https://www.facture.ar/api/invoices \
  -H "x-api-key: tu_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "cuitId": "id-de-tu-cuit",
    "invoiceType": 11,
    "ptoVta": 1,
    "concepto": 2,
    "docTipo": 99,
    "docNro": 0,
    "condicionIVAReceptorId": 5,
    "impNeto": 75000,
    "impTotal": 75000,
    "fchServDesde": "20260901",
    "fchServHasta": "20260930",
    "fchVtoPago": "20261010",
    "description": "Consultoría de marketing digital",
    "items": [
      {
        "description": "Consultoría de marketing digital",
        "quantity": 1,
        "unitPrice": 75000,
        "discount": 0,
        "ivaRate": 0,
        "subtotal": 75000
      }
    ]
  }'
```

### Emitir una Factura A (Responsable Inscripto a Responsable Inscripto)

```javascript
const response = await fetch('https://www.facture.ar/api/invoices', {
  method: 'POST',
  headers: {
    'x-api-key': 'tu_api_key',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    cuitId: 'id-de-tu-cuit',
    invoiceType: 1,               // Factura A
    ptoVta: 1,
    concepto: 2,                  // Servicios
    docTipo: 80,                  // CUIT
    docNro: 30712345678,
    condicionIVAReceptorId: 1,    // IVA Responsable Inscripto
    clientName: 'Cliente Empresa S.R.L.',
    impNeto: 620000,
    impIVA: 130200,
    impTotal: 750200,
    iva: [
      { id: 5, baseImp: 620000, importe: 130200 }   // 21%
    ],
    fchServDesde: '20260901',
    fchServHasta: '20260930',
    fchVtoPago: '20261010',
    items: [
      {
        description: 'Desarrollo de software - Fase 1',
        quantity: 1,
        unitPrice: 500000,
        discount: 0,
        ivaRate: 21,
        subtotal: 500000
      },
      {
        description: 'Licencia anual',
        quantity: 1,
        unitPrice: 120000,
        discount: 0,
        ivaRate: 21,
        subtotal: 120000
      }
    ]
  })
})

const resultado = await response.json()
console.log('Batch ID:', resultado.batchId)
```

<Note>
  Si no mandás `condicionIVAReceptorId` en una factura a un CUIT, Facturear la toma del padrón de ARCA. Si la condición no corresponde a la clase del comprobante (por ejemplo, una Factura A a un Consumidor Final), la API responde `400` antes de pedir el CAE. Ver [Condición frente al IVA del receptor](/es/guides/condicion-iva-receptor).
</Note>

### Respuesta: la factura queda encolada

La emisión es **asincrónica**. La API valida el pedido, lo encola y responde enseguida, todavía sin CAE:

```json
{
  "batch": false,
  "message": "Factura encolada para procesamiento",
  "count": 1,
  "status": "processing",
  "batchId": "cmg1a2b3c0000xyz",
  "queueIdentifiers": ["..."]
}
```

### Obtener el CAE

Con el `batchId` consultás el resultado. Cuando el ítem termina, su `responseBody` trae el id de la factura en Facturear, el número de comprobante y la respuesta de ARCA con el CAE y su vencimiento:

```bash
curl https://www.facture.ar/api/invoices/batches/cmg1a2b3c0000xyz \
  -H "x-api-key: tu_api_key"
```

```json
{
  "id": "cmg1a2b3c0000xyz",
  "status": "completed",
  "totalItems": 1,
  "processedItems": 1,
  "successfulItems": 1,
  "failedItems": 0,
  "environment": "production",
  "items": [
    {
      "id": "cmg1a2b3d0001xyz",
      "status": "completed",
      "requestBody": { "invoiceType": 1, "ptoVta": 1, "impTotal": 750200 },
      "responseBody": {
        "success": true,
        "invoiceId": "cmg1a2b3e0002xyz",
        "voucherNumber": 42,
        "fecaesolicitarResult": {
          "FeDetResp": {
            "FECAEDetResponse": [
              { "Resultado": "A", "CAE": "76123456789012", "CAEFchVto": "20261008" }
            ]
          }
        }
      },
      "cuit": { "id": "id-de-tu-cuit", "number": "20123456789" }
    }
  ]
}
```

Para conocer el resultado, consultá el lote o suscribite a `invoice.completed`/`invoice.failed` con [webhooks](/es/guides/webhook-integracion): Facturear te avisa apenas ARCA aprueba o rechaza la factura. Ver la [documentación completa de la API](/es/api-reference) para todos los parámetros disponibles.

## Casos de uso comunes

### Factura con múltiples alícuotas de IVA

Cuando una factura tiene ítems con diferentes alícuotas (21% y 10,5%), el array `iva` lleva una entrada por alícuota:

```javascript
{
  // ...cuitId, ptoVta, concepto y fechas de servicio como en el ejemplo anterior
  invoiceType: 1,
  docTipo: 80,
  docNro: 30712345678,
  condicionIVAReceptorId: 1,
  impNeto: 230000,
  impIVA: 45150,
  impTotal: 275150,
  iva: [
    { id: 5, baseImp: 200000, importe: 42000 },  // 21%
    { id: 4, baseImp: 30000, importe: 3150 }     // 10,5%
  ],
  items: [
    { description: 'Servicio de catering', quantity: 1, unitPrice: 200000, discount: 0, ivaRate: 21, subtotal: 200000 },
    { description: 'Transporte incluido', quantity: 1, unitPrice: 30000, discount: 0, ivaRate: 10.5, subtotal: 30000 }
  ]
}
```

### Factura con productos exentos e IVA

Lo exento va en `impOpEx` y no entra en el array `iva`:

```javascript
{
  invoiceType: 6,
  concepto: 1,
  docTipo: 99,
  docNro: 0,
  condicionIVAReceptorId: 5,
  impNeto: 3500,
  impIVA: 735,
  impOpEx: 40000,
  impTotal: 44235,
  iva: [
    { id: 5, baseImp: 3500, importe: 735 }   // 21% sobre el envío
  ],
  items: [
    { description: 'Libro técnico', quantity: 5, unitPrice: 8000, discount: 0, ivaRate: 0, subtotal: 40000 },
    { description: 'Envío', quantity: 1, unitPrice: 3500, discount: 0, ivaRate: 21, subtotal: 3500 }
  ]
}
```

### Factura B a cliente identificado

Desde $10.000.000 (y siempre que el cliente quiera quedar identificado), informá su documento y seguí enviando la condición de Consumidor Final. Si falta, la API responde `400` antes de pedir el CAE:

```javascript
{
  invoiceType: 6,                 // Factura B
  docTipo: 96,                    // DNI
  docNro: 12345678,
  condicionIVAReceptorId: 5,      // Consumidor Final
  clientName: 'Juan Carlos Pérez',
  impNeto: 100000,
  impIVA: 21000,
  impTotal: 121000,
  iva: [{ id: 5, baseImp: 100000, importe: 21000 }]
}
```

## Descargar el PDF de una factura

Con el `invoiceId` que devuelve el `responseBody` podés obtener el PDF:

```bash
GET https://www.facture.ar/api/invoices/{invoiceId}/pdf
```

El PDF incluye:
- Todos los datos fiscales
- CAE y fecha de vencimiento
- Código QR con la URL de verificación de ARCA (RG 4892/2020)
- El diseño de tu CUIT: plantilla, logo y color. Ver [Diseño de la factura](/es/guides/diseno-factura)

## ¿Qué pasa si ARCA devuelve un error?

Hay dos momentos en que una factura puede fallar:

- **Al enviarla**: si el cuerpo no es válido (importes que no cierran, condición frente al IVA que no corresponde a la clase, un consumidor final sin identificar en una venta de $10.000.000 o más, etc.), la API responde `400` con `{ "error": "...", "details": ... }`. Si superaste el límite de tu plan, responde `403` con `code: "SUBSCRIPTION_LIMIT_EXCEEDED"`.
- **Al procesarla**: si ARCA rechaza el comprobante, el ítem queda en `status: "error"` y el `responseBody` trae los mensajes de ARCA.

Los errores de ARCA más comunes al emitir:

| Código | Descripción | Solución |
|---|---|---|
| 10013 | CUIT receptor no existe en ARCA | Verificá el CUIT del cliente |
| 10015 | Documento del receptor inválido o faltante: en comprobantes B por montos altos (hoy $10.000.000) el consumidor final tiene que estar identificado, y CUIT, CUIL y CDI se validan contra el padrón | Enviá un `docTipo` distinto de `99` y un `docNro` válido |
| 10043 | Fecha inválida | La fecha no puede ser retroactiva más de 5 días |
| 10044 | CAE vencido | Reintentá la emisión |
| 10067 | Error en alícuota de IVA | Verificá el código de alícuota |

Si encontrás errores persistentes, consultá la [documentación de la API](/es/api-reference) o contactá a [support@facture.ar](mailto:support@facture.ar).
